# 职业双动作策略

## 目标

- **主推荐**：执行当前推荐源的自有队列；源可先做条件完整且可实时证明的精确判断，
  无法判断更高优先级条件时再原样回退 JustAC。随后执行推荐源通过
  `IsBurstCue` 明确标记的爆发提示（JustAC Stage G 为保留 Blizzard 第一推荐可能将
  它放在第 2 位），随后才处理维护技能和普通第一推荐。精确提示只允许表达一个已验证
  的窄条件，不得冒充完整 APL；提示仍须通过安全、可用和快捷键检查。
- **保留爆发版**：面向拉怪跑路和普通 Boss 机制持续按住。火法、冰法、冰 DK、邪 DK
  的内置 12.1 源通过 `GetPreserveQueue()` 从原始 JustAC 队列选择。12.1 奥法是唯一
  例外：M4 使用与 M5 相同的 `arcane121` 自有普通优先级，只跳过奥术涌动和
  大法师之触，且不合并 JustAC 的其他 Burst Trigger。12.1 冰 DK 仍读取原始 JustAC
  队列，但同样使用策略自有的精确保留集。所有专精随后都只取非保留、
  当前可用、已绑定且可移动安全的动作。普通专精即使当前一帧静止，也不启动不可
  移动读条、引导或蓄力；12.1 奥法例外与 M5 共用真实移动判断，静止时允许正常
  奥冲和飞弹，移动时仍必须有精确的移动施法条件。
- 不改变 `SpellQueue.GetCurrentSpellQueue()` 的调用频率，不增加定时等待。

## 维护边界

- 公共选择、版本匹配和玩家覆盖逻辑：`Policies/Registry.lua`
- 法师法术表：`Policies/Mage.lua`
- DK 法术表：`Policies/DeathKnight.lua`
- 兽王猎人法术表：`Policies/Hunter/BeastMastery.lua`
- 推荐源注册与 JustAC 适配：`Sources/Registry.lua`、`Sources/JustAC.lua`
- 场地技能生命周期：`Trackers/GroundEffects.lua`
- `JustACBridge.lua` 只消费已解析策略，不包含职业法术 ID。

新增职业或为新 Interface 版本增加差异时，仅增加/修改对应策略文件及 TOC
加载项；现有 SavedVariables 仍按 `CLASSFILE_<专精序号>` 保存，不需要迁移。

## 兽王猎人

保留爆发版始终跳过狂野怒火 `19574` 和狂野鞭挞 `1264355` / `1264359`，
从原队列选择下一项可执行的普通攻击。两者同时登记到 `reserve` 与
`reserveExclusions`，避免推荐源未识别爆发或已有玩家取消保留覆盖时被重新放行；
当前原队列中没有其他安全动作时，保留版不发送技能，不从高亮注入其他动作。
无损版仍可使用这些技能。

两篇 NGA 奥法文章描述的是 **TWW S3 / 11.2**。其后置触结论依赖当时的四件套、

**Midnight 12.0 起不再沿用该 APL。** 12.0 已移除或重做敏锐直觉、祥和、
虚空精准、白炽耀焰等旧联动，并让唤醒不再提供节能施法或叠层智力增益。因此当前保留版只
扣住奥术涌动和大法师之触；唤醒作为缺蓝时的恢复技能正常通过。策略字段
`reservePassthrough` 会在合并 JustAC Burst Trigger 后再次移除唤醒，避免旧配置
把它错误扣住；玩家仍可用 `/jacb reserve add 12051` 主动改回保留。

12.1 奥法进一步把默认保留集固定为涌动与触，不读取 JustAC Burst Trigger 中的
其他法术，防止旧配置把宝珠、弹幕等普通动作一并扣住。`/jacb reserve` 玩家覆盖
仍在最后应用，因此明确的个人配置不受限制。

12.0 的奥术飞弹不再全局强制在一个 GCD 后截断，恢复普通完整引导。

奥术宝珠 `153626` / 覆盖形态 `153640` 按人物面向发射，而副本内无法可靠取得目标
方位并控制人物转向。12.1 的 M4/M5 在移动中都会排除宝珠，避免处理机制时向错误
方向发射或额外拉怪。加载/重载后以及普通停止移动后，M5/M4 都必须连续静止满 0.8 秒，期间
再次移动会重新计时。闪现 `1953`、闪光术 `212653` 及其 12.1 形态 `1294067` 的
成功施法事件会另行触发两路共同的 2 秒宝珠延迟，即使传送没有产生普通停止移动事件
也不会提前放行。11.2 的 M4 仍维持历史上的永久排除规则。

奥术宝珠是多充能技能。其任一缺失充能正在恢复时，DurationObject 仍为 active，不能
用 `IsSpellOnCooldown` 代表“没有可用层数”。12.1 自有源改用 JustAC 的
`IsSpellReady` 本地充能追踪：`1/2` 返回可用、`0/2` 返回不可用；接口缺失、抛错或返回
secret/unknown 时精确回退 JustAC，不用 DurationObject 猜测最后一层。

奥法不登记通用核心最终兜底。12.1 S2 的当前 SimC 疾咒师/日怒 APL、主流攻略优先级及
JustAC 自带 `MAGE_1` SimC 队列均不包含魔爆术 `1449`；因此 12.1 规则从 M5/M4
两路自动动作排除它。原队列没有其他合格动作时保持空动作，不为了避免空输出而
擅自选择填充技能。手动释放魔爆术不受影响；旧版本仍只从 M4 持续按住动作排除。

12.1 奥法的 `fallback=true` 路径不得重写 JustAC 优先级。过去把奥术冲击移动或注入到
JustAC 弹幕之前的“保守回退”会在 25 层 Arcane Salvo、飞弹可用且更高谓词为 secret
时覆盖 JustAC 已经正确给出的弹幕，造成持续奥冲。该重排现已移除：回退保留安全过滤
后剩余动作的原始相对顺序，也不会补入 JustAC 没有给出的奥冲。Touch 同目标凭据、
M4 保留、移动/引导、方向/地面技能和技能归属/绑定仍作为合法性或安全过滤执行；这些
过滤只能删除不合法动作并继续读取后续原队列，不能注入技能或自行改写 APL。

反方向的移动重排同样禁止：奥冲、飞弹或宝珠因真实移动而被过滤时，原队列后排的
奥术弹幕不能只凭“瞬发且可用”晋升。12.1 策略把 `44425` 登记为
`movementFallbackProofSpells`；移动中只有队列第 2 位及以后的弹幕需要当前源通过
`IsMovementFallbackAllowed` 正面证明正常 APL 弹幕谓词及 readiness，false、nil、
接口缺失或异常全部失败关闭。队首弹幕仍保持源权威；证明失败只删除该候选并继续按
原相对顺序扫描，没有后续安全动作时 M4/M5 合法为空。

12.1 的奥术脉冲 `1241462` 天赋替换魔爆术按钮，棱彩箭 `1295939` 则会动态替换
奥术冲击。推荐源可能返回基础按钮 ID，而实际技能已经变化；Bridge 因此先解析
动态动作栏形态，再解析天赋替换，并对外导出实际技能 ID。魔爆术的排除只匹配解析
后的实际 `1449`，不会误伤奥术脉冲；棱彩箭也按自身零读条形态参与 M4 移动安全
判断，不会被基础奥冲的读条时间错误挡住。Windows M5 因而也不会把奥术脉冲误当
魔爆术套用 `100ms` 观察窗口。

当前可取得的敌人数只是“有玩家仇恨关系的可见姓名板数”，既不是玩家身边精确数量，
也不能证明敌人处于奥术脉冲的目标落点范围。12.1 的两套英雄天赋又使用不同目标阈值，
因此 Bridge 不用该近似值重写奥法单体/AOE 分支，动态优先级继续交给推荐源。

12.1 攻略区分普通与 `Overpowered Missiles` `1277009` 强化飞弹：普通飞弹建议
在下个技能可排队时截断，强化飞弹必须完整引导。但当前实战日志没有足够样本证明
WoW 能让 Bridge 在增益被消耗前稳定读取并绑定到本次引导。按照“不能可靠判断就
不主动截断”的保守原则，12.1 将奥术飞弹登记为 `protectedChannels`，所有飞弹
完整引导。只有已有明确旧版本依据的 11.2 继续使用 `clipChannels`。
12.1 奥法 M4/M5 都使用这项精确条件移动施法；静止时两者也都能启动飞弹。飞弹一旦
开始，`protectedChannels` 会锁住两个输出直到真实停止/中断事件，不会被按住键截断。

霜火冰在明确超过 20 码、已学霜火之箭且 JustAC 当前给出“冰川尖刺→冰风暴”时，
会从原队列提前选择已绑定且可用的冰风暴，避免套装火球失去碎冰。无法确认距离时
保持原顺序，不根据猜测改技能。

冰霜射线登记在 `protectedChannels`，必须完整引导。即使 WoW 在引导期间反复发出
移动事件，Bridge 也会继续保护该引导，不会因为持续按住 M4/M5 而在 GCD 结束时
发送冰风暴、冰枪术等下一技能将其提前截断。只有玩家自行移动或主动取消才会中断。

法师移动兜底只在原队列没有安全动作时启用：火焰用灼烧 `2948`、冰霜用冰枪术
`30455`；奥术没有人为兜底。这些兜底仍需通过已学习、可用、射程和快捷键检查。

12.1 奥法棱光护体 `235450` 会占用伤害 GCD，因此不加入 M5；M4 持续按住时则作为
防御维护动作优先插入，但仅在 Buff 明确不存在、法术已学习、当前可用、冷却明确就绪
且快捷键已绑定时释放，任何状态未知都跳过。冰法寒冰护体 `11426` 仍保留额外充能
维护：只有 Buff 明确不存在、法术已学习、当前充能数明确大于 `1` 且快捷键已绑定时
才自动释放，始终留下 `1` 层供手动应对机制。

12.1 奥法 M5 改由 `Sources/Arcane121.lua` 自有源决策，不再用策略层给 JustAC 队列
打补丁。当前源只实现能够由运行时证据完整证明的普通优先级切片；药水、秘密层数、
持续时间或动态优先级等任一更高条件无法证明时，立即原样返回 JustAC 队列并在日志
写出 `SOURCE_DECISION ... fallback=true`。自有源不能证明比 JustAC 更正确时不得用
奥冲或其他动作覆盖原推荐；这仍是可验证切片加精确回退，不宣称复刻完整 SimC APL。

12.1 M5 采用用户明确指定的可靠性优先规则；这条项目规则优先于需要额外飞行/引导
时序的攻略高级序列：

- M5 在涌动和触都明确就绪时立即选择涌动；涌动成功后建立最长 10 秒的
  `EXPECT_TOUCH`，下一动作直接优先触。只有服务器成功事件建立/完成，失败、中断、
  意外 GCD、超时或无效目标都会取消。M4 始终保留两技能，不强制这条配对。
- 涌动→触凭据绑定建立时的敌对目标 GUID。目标变化、死亡或变为
  不可攻击会同时清除源层和核心配对层凭据，切回旧目标也不会恢复。
- 涌动被正面证明未学习、未绑定、不可用或正在冷却时，触明确就绪就直接释放；不要求
  上一弹幕/Bolt，也不读取 DurationObject 或任何剩余冷却阈值。涌动就绪状态未知时
  仍失败关闭，不能猜测直放触。

12.1 火法、冰法也分别由 `Sources/Fire121.lua`、`Sources/FrostMage121.lua` 独立决策：

- 火法区分炎爆术瞬发 Hot Streak/Hyperthermia 与 Pyroclasm 读条形态，三目标且已学
  Fuel the Fire 才切烈焰风暴；实现 Firestarter 保留、可观测燃烧窗、日怒燃烧内流星、
  Heating Up 空闲帧火冲和 Heat Shimmer/Scald 灼烧。燃烧前置读条由成功施法事件确认，
  随后在首个空闲帧发送燃烧，以保留仍在飞行的弹道；Bridge 在任意读条期间禁止持续
  按键注入，因此仍不伪造“读条结束前约 150ms 燃烧/火冲”的双法术编织。
- 冰法按服务器确认的施法事件推进霜火/疾咒师开场，覆盖冰川尖刺、彗星风暴、
  脑部冻结、寒冰指、宝珠、暴风雪阈值、Freezing 层数与英雄天赋分支。冰霜射线总是
  完整引导；SimC 的按射线跳数截断、不可可靠读取的冰刺数，以及秘密的套装时序均回退
  JustAC，不用固定时间近似。

两者都先保留原队列中的物品头部，让 JustAC 继续决定饰品/药水时序；M4 永远不用
自有队列，移动时仍由策略层跳过所有不可移动读条、引导和蓄力。

专精登记的最终兜底法术不参与失败熔断。它已经是没有更安全动作时的最后选择，
即使游戏返回施法失败，也不会累计失败次数或将该兜底临时屏蔽。

已登记最终兜底的专精会为 M4/M5 提供非空保证：正常队列选不出动作时尝试专精兜底
快捷键；M4 仍要求兜底本身可移动施放。射程和运行时 `usable` 结果只写入诊断日志，
不再把合格兜底过滤成空动作。奥法与 12.1 冰/邪 DK 未登记兜底，因此允许输出为空。

普通推荐除 JustAC 的 `IsSpellUsable` 外还检查实际冷却/充能剩余时间。JustAC
队列短暂滞留在刚释放、仍处于冷却的冰风暴等技能时，Bridge 会立即跳过该条目，
避免 Windows 反复发送同一个必定失败的快捷键，并最终落到冰枪术兜底。

保留版不会扣住普通符文/符能消耗技能；它从 JustAC 队列继续选择可用填充技能，

DK 的 M4 不自动猜测“这群怪还能活多久”；玩家按住 M4 本身就是跑机制或清理尾怪的

12.1 邪 DK M5 额外按亡者大军的当前冷却决定黑暗突变时机：严格大于 30 秒可单独
开黑暗突变；恰好 30 秒及以下则扣住黑暗突变。大军转好后仍尊重原推荐源在其前面的
疾病和脓疮镰刀准备，只有原队首确实给出大军且两技均已就绪时才启动成组动作；
收到大军成功施法事件后再发黑暗突变。缺失、隐藏或异常的冷却/可用证据不能冒充
`>30`。选择器或源异常时仍过滤这两个成组技能，防止普通兜底绕过；M4 继续使用
自己的保留队列。该阈值与[当前 SimC 邪 DK APL](https://github.com/simulationcraft/simc/blob/midnight/ActionPriorityLists/default/deathknight_unholy.simc)一致。

冰 DK 的冰霜巨龙之怒 `279302` 另有严格顺序门：只有
`UNIT_SPELLCAST_SUCCEEDED` 已记录到比上一次冰霜巨龙之怒更新的冰霜之柱 `51271`，
且该成功事件距今不足 10 秒，或当前能明确读取到冰霜之柱光环时才可执行。冷却/可用
状态不作为顺序证据；门未满足时 Bridge 跳过该动作并继续扫描 JustAC 队列。冰霜之柱
基础持续 12 秒，但光环隐藏时只使用更保守的 10 秒事件窗口；旧记录不会一直等到后续
巨龙之怒冷却转好。离开战斗、进入世界或切换专精时也会清空历史。

霜裔天选者的二次释放不套用上述首发顺序门。只有 JustAC 的实时有效法术解析明确显示
冰霜巨龙之怒按钮已覆盖为召回法术 `1265384` 时，Bridge 才精确识别为二次释放并完全
按 JustAC 放行；没有覆盖 ID 的确定证据就不猜测、不模拟召回窗口。

冰 DK 的 M4 还启用“仅原队列”模式。凛风冲击 `49184` 只有实际出现在当前 JustAC
队列中才可被 M4 选中；Bridge 不把“可用”“高亮”或单独读到 Proc 当成 JustAC 已推荐
该技能的替代证据，也不在队列缺失时调用专精兜底补入凛风冲击。这样离开近战时严格
保持“有 JustAC 凛风提示就喷，没有提示就跑”。

M5 只在 JustAC 的已知法术射程探针明确返回目标超过 5 码时采用相同规则：此时只允许
当前原队列中的凛风冲击，其他动作与所有注入/兜底都暂停；队列没有凛风冲击便保持
为空。距离为 `nil` 或 secret 时不猜目标位置，继续保留 M5 原行为；因此该修正不会把
一次不确定射程误当成跑机制。

首次冰霜巨龙之怒 `279302` 的成功事件会为 M5 打开 4 秒亡者复生 `46585` 跟随窗口。
跟随项高于当前 JustAC 队列，但必须由技能归属、真实快捷键、可用状态以及 JustAC 的
隐藏冷却控件共同证明可执行。亡者复生明确在冷却，或冷却结果未知/secret 时，本次
窗口立即作废并在同一帧回到原 JustAC 队列，不会等待冷却。召回覆盖 `1265384` 使用
精确事件 ID 排除，不会被误当成首次巨龙之怒再次触发；M4 不执行这条跟随。

### 12.1 M5 大小爆发协调与龙喷资源门（2.13.13 / Frost r28）

这是用户明确指定的爆发协调规则，不是完整 APL 或经过实测的最高 DPS 声明。
2026-09-27 核对 [Method 12.1 手法](https://www.method.gg/guides/frost-death-knight/playstyle-and-rotation)
和 [Icy Veins 吐息手法](https://www.icy-veins.com/wow/frost-death-knight-pve-dps-rotation-cooldowns-abilities)：
计划与冰柱配对的吐息需要准备 60 符能；并非每一个小冰柱窗口都等待吐息。

- M5 在任何普通推荐之前检查：冰柱 `51271`、当前吐息 `1249658`、首次龙怒
  `279302` 均明确已学习、有真实绑定。开怪前同样检查，不让第一发冰柱绕过资源门。
- 尚未满足逐步启动时限时，只有三者都已就绪或当前排除 GCD 的剩余冷却**严格小于 6 秒**，
  且已学习、已绑定的印记也就绪或在 6 秒内，才进入 `PREP_BREATH_WITHIN_6S`。
  恰好 6 秒在下一次小于 6 秒的刷新才开始；6 秒是用户指定的准备范围，不是普适最优 APL。
  此时只在 JustAC 当前原队列中过滤需要保留的耗能动作；达到下面的逐步启动时限后，
  不再机械等待后继 CD 同时归零。
- 提前准备并非一律不花符能：实时读取当前有效动作的固定消耗，只有能证明
  **当前符能 ≥ 60 + 该动作消耗** 才放行。消耗 35 时 95 可放、90 不放；消耗 25 时
  85 可放，避免按固定 85/90 阈值错误泄能。不猜天赋减耗或满条上限；条件、可变、
  持续消耗及未知资源保守处理，无法证明时不能承诺完全避免溢出。
- 剩余冷却/资源明文可读时直接判断；隐藏时用原生 Step 曲线当前求值。曲线必须先
  通过边界自检，只输出 0/100 二值，不能使用近似斜坡或取整百分比，更不复用旧帧结果。
  引擎/适配能力缺失导致近窗无法证明时，不假装进入准备；普通动作保序，但四个爆发仍禁止散放。
- 逐步冷却时限满足而吐息当前资源不足/可用性未知时，进入 `POOL_BREATH`：保留这轮印记、冰柱、
  吐息、龙怒，过滤冰打 `49143`（含霜害覆盖 `1228433`）、冰川突进 `194913`、灵界打击 `49998` 等列出的
  符能消耗动作。其他动作沿用 JustAC 当前队列的原始顺序，包括其推荐的湮灭、
  凛风冲击、符文武器增效；不另造普通循环或强插增效。手动保命不受推荐过滤控制。
- 过滤后没有合法队列动作时，M5 允许暂时为空，不允许后续兜底把刚扣住的冰柱或
  消耗动作重新塞回来。不会把增效成功事件当成符能已经到账，逐帧重读可施放性。
- 可读符能必须至少 60；数值隐藏时，只接受原生法术接口或验证过法术归属的实体
  动作栏按钮对该吐息实时返回“可用且不缺资源”。不接受 fail-open、缓存值或估计。
- 吐息确认资源够且整组逐步时限满足后，按 **印记 → 冰柱 → 吐息 → 首次龙怒** 输出。
  印记为必需前置：未学、未绑、冷却中、暂缺符文或状态未知都不能跳过并单开冰柱。
  每一步只由玩家真实 `UNIT_SPELLCAST_SUCCEEDED` 推进；重复推荐不算施法。
  资源达到门槛即开始，不为了储能等到 100，也不在够能时额外强插增效。
- 已进入冰柱窗口后资源突然不足，仍扣住龙怒，继续原队列回能，恢复后再补吐息。
  M5 按住产生的 GCD、缺资源失败不会被误当成“放弃吐息、直接龙怒”的指令。
  冷却更新先于成功事件时，短暂等待成功凭据，不能据此跳过当前步骤。
- **严格分组与 18 秒对齐（2.13.10）**：印记＋冰柱、龙喷＋首次龙怒分别为一组。
  唯一允许的形状为 **印记 → 冰柱**、**印记 → 冰柱 → 龙喷 → 首次龙怒**。
  只有两龙都被正面证明冷却中，且当前剩余都**严格大于 18 秒**，才选择小组。
  任一已好或在 18 秒内（含恰好 18 秒）就等大组；一条 0 秒另一条 35 秒也不能
  单开其中一条。未知不等于长 CD。18 秒是本用户指定的对齐阈值，不是攻略最优结论。
  在等待中正常使用原队列普通动作，不从 18 秒前就憋符能；仅共同 6 秒近窗才准备。
- **小窗口**不保留 60 符能，印记当前可用且冰柱到轮到它时可接上便启动，以成功事件推进，不能单放冰柱。
  印记当前明确缺资源时不继续消耗其所需符文；小组已成功启动后不因两龙冷却改变
  追加龙喷/龙怒。未成功的建议不是窗口承诺，必须继续检查当前分组条件。
- **所有退出仍保留分组门**：缺技能、未绑、冷却未知、目标重置、完成、选择器 nil
  或异常都只回退到删除组内技能后的原队列；不再允许源 cue 或兜底漏出单个爆发。
  召回 `1265384` 是唯一明确的独立覆盖动作，仍交给 JustAC，但不会一起放行冰柱/龙喷。
- 18 秒边界明文直接严格比较。隐藏值使用经过原生自检的 Step 阶梯，区分 18 与
  下一个可表示 double；若引擎精度不能区分，则仅接受 `>=19` 对 `>18` 的充分证明，
  [18,19) 无法细分时等待，不猜成“小组”。这是保守不确定区间，不是把阈值改成 19；
  已知值仍按 18 精确判断。客户端真实曲线精度仍需实战证据，离线不能保证。
- 状态绑定敌对目标；换目标、目标无效、脱战、切专精/天赋、进入世界等会重置。
  已确认 5 码外仍仅允许原队列中的凛风冲击。活动序列每步最多 10 秒，且冰柱成功
  后绝不越过既有 10 秒顺序证据窗口；手动乱序成功会取消旧序列。
  完成后保留原有“首次龙怒 → 亡者复生”跟随。M4、旧版和其他专精不启用资源门。
- 冷却、技能归属或绑定无法可靠证明时，不能声称三者已好；原推荐源保序且过滤四个组内爆发；
  三冷却已确认时可施放性仍未知，则不贸然开爆发。日志 `SELECT.preparationReason`
  区分 `PREP_BREATH_WITHIN_6S`、`POOL_BREATH`、`EXPECT_MARK/PILLAR/BREATH/FURY`、
  确认等待与退出原因；准备日志列出候选消耗及花费后够能的 true/false/nil，近窗不满足
  时列出阻断技能和判定结果，便于实际 API 复盘。

**2.13.12 逐步时限：** 印记当前可放、资源已足够，后继 CD 在轮到它的时限内即可启动。
使用 `ActionSequence:CanStartCooldowns` 声明式机制：印记贡献一个当前急速 GCD，
冰柱、龙喷贡献零个，因此不能把四个按钮错误当作四个 GCD；当前已在 GCD 中时再加
真实剩余 GCD 的起手偏移。没有额外网延/任意毫秒放宽，只有严格受限的机器舍入界。
成功后只按当前步骤检查，正常后继短 CD 不再触发取消，不能被普通 GCD 插队。
大组仍需当前 60 符能，小组不保留符能；18 秒分组、6 秒准备、M4 和其他职业均不变。
急速隐藏时仅用已知最短 GCD 的充分条件；CD 证据未知或原生精度不足仍可能等待。
详细接口、证据与验证见 `Framework/README.md`，未承诺真实客户端百分之百无损。

**2.13.13 公共模式隔离：** 资源准备只在明确的 M5/lossless 上下文启用。M4 不读

## DK 场地技能与冷却就绪

枯萎凋零 `43265` 与亵渎 `152280` 共享 `death-and-decay` 场地规则：

- 监听玩家自己的 `UNIT_SPELLCAST_SUCCEEDED`，仅在服务器确认实际放置后开始；
- 打开绿色选点圈但没有完成放置不会误计时；
- 默认持续 `10` 秒，再次成功施放会刷新 `placedAt/expiresAt`；
- 仍有效时跳过队列中的重复枯萎凋零/亵渎，并选择后续安全动作；
- `/jacb ground off` 只关闭重复过滤，倒计时和导出仍保留；
- `/jacb ground reset` 可处理取消、特殊 encounter 重置等异常情况。
- 场地 10 秒到期只解除重复推荐过滤，不再发提醒；每次服务器确认施放后进入固定
  30 秒顺序充能计时，不读取大秘境战斗中的 secret 冷却起止值；
- 两层都消耗时，第一个 30 秒结束显示并播报“枯萎凋零1”，再过 30 秒显示并播报
  “枯萎凋零2”；只有一次施放时，30 秒后直接提示“枯萎凋零2”；
- 可分别用 `/jacb cooldown alert/sound/voice on|off` 控制，`/jacb cooldown test`
  可立即验证；旧的 `/jacb ground alert/sound/voice` 与 `ground test` 仍作为兼容别名。

WoW 不提供可持久查询的场地对象句柄，因此追踪的是“成功放置时间 + 职业策略
持续时间”，不依赖目标坐标或伤害跳数；即使场内暂时没有敌人也不会提前丢失。

## 主动饰品和药水

JustAC 队列用负数表示物品。保留版默认跳过所有物品，避免自动消耗药水或主动
饰品；主推荐静止时仍完整执行第一推荐。

饰品槽 1（13）和饰品槽 2（14）使用 `C_Item.GetItemSpell` 判断是否存在主动效果，
再把 `GetInventoryItemCooldown` 返回的实时冷却交给隐藏 `Cooldown` 控件。控件的
`OnCooldownDone` 是完成依据，不对 12.x 战斗中的 secret 起止时间做算术或猜测。
因此可单独监控主动饰品，纯被动/触发型饰品会被排除；登录、重载或换装时发现
一个主动饰品已经在冷却，也会继续监控到完成。

## 移动过滤

默认启用 `/jacb movement on`。玩家移动时：

- 基础瞬发技能和物品允许执行；
- JustAC `IsSpellProcced` 明确报告当前 Proc 的读条技能按瞬发处理；
- JustAC 的引导技能表同时覆盖普通引导和 Evoker 蓄力技能，默认跳过；
- 职业策略的 `moveCastAlways`、`moveCastBuffs` 可登记灼烧、浮冰一类例外；
- 12.1 奥法只有在浮光掠影 `236457` 已学习且节能施法 `263725` 光环存在时，才把
  奥术飞弹 `5143` 视为可移动引导；气定神闲 `205025` 光环存在时，才把奥术冲击
  `30451` 视为移动安全的瞬发。任一 API 状态未知都会保守跳过；
- 冰川尖刺的旧版/当前覆盖 ID `199786`/`1236209` 登记为移动时强制跳过，
  优先级高于覆盖按钮的 Proc 高亮及移动施法例外；
- 寒冰箭、霜火替换形态及暴风雪 `116`/`431044`/`468655`/`190356` 不使用
  推荐高亮或浮冰推断瞬发；只有当前有效法术形态被 API 明确报告为零读条时，
  才允许移动施放；
- 无法确认是否可移动施放时保守跳过，不向动作队列发送该技能。
- 只有原队列前 8 项全部没有安全、可用且已绑定动作，且当前策略显式登记兜底时才进入
  职业兜底；M5/M4 共用兜底数据，M4 额外要求动作可移动施放，并排除爆发、药水和
  主动饰品。未登记兜底的专精保持空动作。
- 若移动中某个当前推荐在 300 ms 内连续被游戏拒绝 3 次，则短暂跳过该动作并
  继续扫描；没有其他可执行项时仅尝试策略显式登记的兜底，否则保持为空。
- 战斗中速度属于受保护数据时，以移动事件为准；同帧开始/停止事件会防抖，移动
  意图可以打断本就无法移动维持的引导，不会让 M4/M5 永久停在引导保护。

所有导出到 Windows M5 的动作都必须存在实际快捷键绑定，包括自有推荐源插入到队首的
精确动作。若队首动作未绑定，核心会继续扫描后续已绑定动作；策略登记了最终兜底才会
继续尝试，否则保持为空。绝不导出一个红色“未绑定”动作并吞掉 M5。冰法彗星风暴等
自有源动作同样遵守此规则。

此外，可用性与冷却返回值不证明当前天赋实际拥有某法术。12.1 自有源在判断任何动作
就绪前必须由 `IsPlayerSpell`/`IsSpellKnown` 正面确认技能归属；当前冰法构筑未学习
彗星风暴时，即使 JustAC 的封装把 `153595` 报告为可用，也不得把它加入推荐队列。

## 射程过滤

默认启用 `/jacb range on`。Bridge 复用 JustAC
`SpellQueue.IsConfirmedOutOfRange`，其底层读取
`C_Spell.IsSpellInRange(spellID, "target")`：

- 只有明确返回超出射程时才跳过，并继续扫描原 JustAC 队列；
- 自身技能、无目标技能、地面技能或 API 无法确认时保持原推荐；
- 近战技能离开 Boss 射程后可自动选择后续远程技能或突进技能；
- `/jacb range off` 可恢复不做射程过滤的行为。

## 玩家覆盖

覆盖按当前专精保存：

```text
/jacb reserve list
/jacb reserve add <法术ID>
/jacb reserve remove <法术ID>
/jacb reserve reset
```

`remove` 表示显式排除，即使该技能来自内置表或 JustAC Burst Trigger，也不会
再被保留。
