# JustACBridge M4/M5

原生 Windows 实时映射器：连续读取 `PIXEL_PROTOCOL.md` 的双动作数据，默认把 **M5** 映射为无损版，把 **M4** 映射为保留爆发版。

按住任一功能键后，客户端只在 GCD 空闲或最后约 120 ms 的入队窗口内，以
20 ms 周期持续跟随最新推荐连发。GCD 尚早时会保留物理按住状态但不发送技能，
让后续 Proc、资源和目标变化有时间更新推荐，避免旧动作过早占用 WoW 技能队列。
GCD 空闲时首次按下和推荐变化仍会立即触发。

当协议报告玩家正在持续引导（`0x40`）、普通读条或蓄力施法（`0x80`）时，程序会**立即暂停连发并完全吞掉两个功能键事件**。程序会记住物理功能键仍处于按下状态；只有读到校验正确且明确为空闲状态的数据包后才自动继续，因此不会用连发打断自己的读条、蓄力或引导。

## 使用

1. 在 WoW 内输入 `/jacb pixels on`。
2. 保证 WoW 窗口可见、左上角像素矩阵未被其他窗口遮挡。
3. 双击 `JustACBridge.M5.exe`；看到绿色“实时映射已启用”后即可使用 M5/M4。
4. 如需换键，点击对应的“设置功能键”，随后按一下 M4、M5 或键盘键。若新键已被另一个功能占用，两者自动交换。
5. 如果 WoW 以管理员身份运行，本程序也应以管理员身份运行，否则 Windows 会阻止输入注入。

每次连发都使用完整的“按下 + 松开”脉冲，不会让虚拟快捷键长期处于按下状态。松开物理功能键后立即停止。无有效推荐、未绑定或不支持的键不会拦截对应功能键。

客户端同时识别 JustAC 的紧凑快捷键格式，例如 `S5` = `SHIFT-5`、`SV` = `SHIFT-V`、`C1` = `CTRL-1`、`M4` = `BUTTON4`。

## 延迟路径

- “极限”模式无主动 `Sleep`，专用最高优先级线程连续执行小区域 GDI 捕获。
- 只在几何参数丢失时搜索 `pitch=2.00..6.00`；稳定后直接解码 576 bit。
- 低级键盘/鼠标钩子在独立最高优先级消息线程中运行；功能键到 `SendInput` 不经过 UI。
- GCD 空闲时首次按下和推荐更新立即发送；GCD 内仅在最后约 120 ms 开放连发。
- v3 像素包携带入队门控和 GCD 剩余时间；读取 v1/v2 时保持旧版兼容连发。
- 映射配置保存在 `%LOCALAPPDATA%\JustACBridge.M5\settings.json`。
- 三项校验全部通过后才原子更新当前快捷键。

零延迟在现实系统中不可能；本程序不额外排队，通常额外延迟受一次屏幕捕获/桌面合成刷新限制。GDI 路径要求游戏可见且不被遮挡。

## 构建

```powershell
dotnet publish .\JustACBridge.M5.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

输出位于 `bin\Release\net10.0-windows\win-x64\publish\JustACBridge.M5.exe`。
