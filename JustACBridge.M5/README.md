# JustACBridge M4/M5

原生 Windows 实时映射器：连续读取 `PIXEL_PROTOCOL.md` 的双动作数据，默认把 **M5** 映射为无损版，把 **M4** 映射为保留爆发版。

12.1 法师三系默认使用各自的插件内置自有源，只有更高优先级条件无法可靠判断时才
回退 JustAC。火法、冰法 M4 读取原始 JustAC 队列；奥法 M4 是专属例外，继续执行
`arcane121` 已证明的普通优先级，但跳过奥术涌动和大法师之触。
移动过滤开启时：M5 静止状态保持完整第一推荐，移动时跳过不可移动读条并允许职业
规则明确证明的条件移动技能；普通专精的 M4 无论某一帧是否静止都跳过读条、蓄力和
所有引导。12.1 奥法 M4 与 M5 共用真实移动安全判断，静止时可读奥冲并完整引导飞弹。
奥术宝珠在移动中两路都跳过；普通停止移动后 M5 立即恢复，M4 连续静止 2 秒后恢复；
闪现/闪光术成功施放后两路都等待 2 秒。
插件还会跳过明确超出当前目标射程的动作；无法确认射程时保持原推荐。

按住任一功能键后，客户端只在 GCD 空闲或最后约 120 ms 的入队窗口内，以
20 ms 周期持续跟随最新推荐连发。GCD 尚早时会保留物理按住状态但不发送技能，
让后续 Proc、资源和目标变化有时间更新推荐，避免旧动作过早占用 WoW 技能队列。
除下述魔爆术稳定性观察外，GCD 空闲时首次按下和推荐变化仍会立即触发。
当前动作携带 `offGCD` 标记时只对对应槽位绕过上述 GCD 门控；另一槽仍按自己的
`queueReady` 状态处理。读条、蓄力和受保护引导的全局屏蔽优先级仍高于该标记。

当协议报告玩家正在受保护的持续引导（`0x40`）、普通读条或蓄力施法
（`0x80`）时，程序会**立即暂停连发并完全吞掉两个功能键事件**。程序会记住
物理功能键仍处于按下状态；只有读到校验正确且明确为空闲状态的数据包后才自动
继续，因此不会意外打断施法。只有对应游戏版本的职业策略明确登记为可主动截断的
引导才不会设置 `0x40`，但 v3 GCD 门控仍保证只在最后约 120 ms 发送下一动作。
12.1 奥术飞弹当前全部按受保护引导处理，不在无法可靠区分强化飞弹时猜测截断。

## 使用

1. 在 WoW 内输入 `/jacb pixels on`。
2. 保证 WoW 窗口可见、左上角像素矩阵未被其他窗口遮挡。
3. 双击 `JustACBridge.M5.exe`；看到绿色“实时映射已启用”后即可使用 M5/M4。
4. 如需换键，点击对应的“设置功能键”，随后按一下 M4、M5 或键盘键。若新键已被另一个功能占用，两者自动交换。
5. 如果 WoW 以管理员身份运行，本程序也应以管理员身份运行，否则 Windows 会阻止输入注入。

按住功能键触发暴风雪选区后，如果用右键取消，映射器会在 3 秒内跳过暴风雪；
冰法会直接改用本次运行中最近识别到的冰枪术快捷键兜底，不再等待 JustAC 队列
自行切换。尚未识别到冰枪术快捷键时才保持不发送。

每次连发都使用完整的“按下 + 松开”脉冲，不会让虚拟快捷键长期处于按下状态。松开物理功能键后立即停止。无有效推荐、未绑定或不支持的键不会拦截对应功能键。

客户端同时识别 JustAC 的紧凑快捷键格式，例如 `S5` = `SHIFT-5`、`SV` = `SHIFT-V`、`C1` = `CTRL-1`、`M4` = `BUTTON4`。

## 延迟路径

- “极限”模式无主动 `Sleep`，专用最高优先级线程连续执行小区域 GDI 捕获。
- 只在几何参数丢失时搜索 `pitch=2.00..6.00`；稳定后直接解码 576 bit。
- 低级键盘/鼠标钩子在独立最高优先级消息线程中运行；功能键到 `SendInput` 不经过 UI。
- M5 无损位遇到魔爆术 `1449` 时先观察 `100ms`；推荐保持不变才释放，期间变为其他
  技能则立即采用新推荐。松开功能键、像素协议失效或进入施法保护都会取消本次等待。
- WoW 插件 `2.10.15+` 会导出当前实际法术 ID；同一基础按钮被奥术脉冲
  `1241462` 替换时不会被误当成魔爆术等待。
- 除魔爆术稳定性观察外，GCD 空闲时首次按下和推荐更新立即发送；GCD 内仅在最后约
  `120ms` 开放连发。
- v3 像素包携带入队门控和 GCD 剩余时间；读取 v1/v2 时保持旧版兼容连发。
- 映射配置保存在 `%LOCALAPPDATA%\JustACBridge.M5\settings.json`。
- 三项校验全部通过后才原子更新当前快捷键。

零延迟在现实系统中不可能；本程序不额外排队，通常额外延迟受一次屏幕捕获/桌面合成刷新限制。GDI 路径要求游戏可见且不被遮挡。

## 构建

```powershell
dotnet publish .\JustACBridge.M5.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

输出位于 `bin\Release\net10.0-windows\win-x64\publish\JustACBridge.M5.exe`。
## 可选诊断

正式版默认不写诊断日志。仅在复现问题前勾选 Windows 客户端中的
`启用诊断日志（仅排错时）`，并在游戏内执行 `/jacb debug on`。复现后点击
`复制完整诊断日志`，再用 `/jacb debug` 复制魔兽端判定；排查结束后关闭两端开关。
